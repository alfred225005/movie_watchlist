# MovieShelf — MERN Stack Movie Watchlist Manager

A responsive movie watchlist built with MongoDB Atlas, Express, React, and Node.js. The backend owns all business rules; the React frontend calls the REST API for every operation.

## Features

- Add, list, search, filter, paginate (6 per page), edit, and delete movies.
- Movie code generated on the backend: `MV-<release year>-<3-digit sequence>`, with a separate atomic counter per year.
- Case-insensitive duplicate detection for title + release year (HTTP 409).
- Frontend and backend validation for release year, runtime, genre, platform, and priority.
- Status workflow: `To Watch` → `Watching` or `Watched`; `Watching` → `To Watch` or `Watched`; `Watched` is final.
- Rating 1–10 required when marking a movie Watched; watched date generated by the backend; rating editable only after Watched.
- Watch Next selects highest priority, then shortest runtime.
- Backend statistics: status totals, hours watched, average watched rating, and most-watched genre.
- Watching movies cannot be deleted, enforced by the backend and disabled in the UI.
- Responsive layout for desktop and mobile.

## Requirements

- Node.js 18 or newer
- npm
- MongoDB Atlas database (or a local MongoDB connection string)
- Git (for version control)

## 1. Configure MongoDB Atlas

1. Create a free cluster at https://www.mongodb.com/cloud/atlas.
2. Create a database user and password.
3. Under Network Access, allow your development IP address. For temporary testing only, you may allow `0.0.0.0/0`; restrict this before production.
4. Select **Connect → Drivers**, copy the connection string, and replace the username/password placeholders.

## 2. Configure and run the backend

Open a terminal in the project root:

```bash
cd backend
npm install
```

Copy `.env.example` to `.env` and edit the values:

```env
PORT=5000
MONGODB_URI=mongodb+srv://YOUR_USER:YOUR_PASSWORD@YOUR_CLUSTER.mongodb.net/movie_watchlist?retryWrites=true&w=majority
CLIENT_URL=http://localhost:5173
```

Do not commit `.env` or real credentials to a public repository. The `.gitignore` excludes it. Start the backend:

```bash
npm run dev
```

Expected terminal output:

```text
Connected to MongoDB Atlas
API server running on http://localhost:5000
```

Health check: http://localhost:5000/api/health

## 3. Run the React frontend

Open a second VS Code terminal at the project root:

```bash
cd frontend
npm install
```

Copy `frontend/.env.example` to `frontend/.env` if you need to change the API URL. Default is `http://localhost:5000/api`.

```bash
npm run dev
```

Open the URL Vite prints, normally http://localhost:5173.

## API reference

All responses use `{ "success": boolean, "message": string, "data": any }`.

| Method | Endpoint | Description |
|---|---|---|
| GET | `/api/health` | API health check |
| POST | `/api/movies` | Create a movie |
| GET | `/api/movies?page=1&status=To%20Watch&genre=Action&search=batman` | Search/filter movies; fixed page size of 6 |
| GET | `/api/movies/:id` | Get one movie |
| PUT | `/api/movies/:id` | Edit title, genre, runtime, platform, priority only |
| PATCH | `/api/movies/:id/status` | Change status; rating required when status becomes Watched |
| PATCH | `/api/movies/:id/rating` | Edit rating for a Watched movie |
| DELETE | `/api/movies/:id` | Delete unless status is Watching |
| GET | `/api/movies/watch-next` | Highest-priority To Watch movie; shortest runtime breaks ties |
| GET | `/api/movies/stats` | Dashboard statistics |

### Example create request

```json
{
  "title": "Interstellar",
  "genre": "Sci-Fi",
  "releaseYear": 2014,
  "runtime": 169,
  "platform": "Other",
  "priority": 5
}
```

The backend creates the movie with `To Watch` status and a generated movie code. Do not send `movieCode`, `status`, `rating`, or `watchedDate` in the create request.

### Example status change

```json
{ "status": "Watched", "rating": 9 }
```

## Deployment notes

- Deploy the backend as a Node web service and set `MONGODB_URI`, `CLIENT_URL`, and `PORT` as environment variables in the hosting provider. The app listens on the assigned `PORT`.
- Deploy the frontend as a static site and set `VITE_API_URL` to the deployed backend's `/api` URL, then rebuild.
- Update backend `CLIENT_URL` to the deployed frontend origin.
- Add the deployed backend's network access requirements to Atlas and never expose database credentials in frontend environment variables.
- For production, consider rate limiting, structured logging, automated tests, and stricter CORS/origin configuration.

## Important implementation notes

- The per-year counter increments atomically, so simultaneous requests don't reuse the same sequence. If a request fails after the counter increments, a sequence number can be skipped; codes remain unique and increasing.
- A unique compound index protects duplicate title/year pairs even if two create requests arrive at nearly the same time.
- The API always enforces the status, rating, edit, and delete rules independently of the frontend.
